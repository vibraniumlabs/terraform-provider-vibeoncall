# vibeoncall_schedule (Resource)

An on-call schedule and its rotations.

~> **Note** The first participant is on call from `start_date`, and the rest follow in `participant_ids` order. Removing a participant can change who is on call now. To keep the current responder, list them first and set `start_date` to the date their current shift started.

~> **Note** Rotations are matched to existing ones by name, and rotations sharing a name by their order. Removing one of two rotations with the same name removes the later one. Moving a rotation to a new position rewrites the rotations in place by position, and the plan shows a warning when it does. Anything that targets a rotation by ID, such as overrides, escalation policies and routing rules, stays with the position, not the rotation you moved, so a policy can start paging a different rotation.

## Example Usage

```terraform
data "vibeoncall_member" "ada" {
  email = "ada@example.com"
}

resource "vibeoncall_team_membership" "ada" {
  team_id = vibeoncall_team.sre.id
  user_id = data.vibeoncall_member.ada.id

  lifecycle {
    create_before_destroy = true
  }
}

data "vibeoncall_member" "alan" {
  email = "alan@example.com"
}

resource "vibeoncall_team_membership" "alan" {
  team_id = vibeoncall_team.sre.id
  user_id = data.vibeoncall_member.alan.id

  lifecycle {
    create_before_destroy = true
  }
}

resource "vibeoncall_schedule" "sre" {
  name      = "SRE primary"
  time_zone = "America/New_York"
  team_ids  = [vibeoncall_team.sre.id]

  rotations = [
    {
      # Hands off every Monday at 09:00 and covers the whole week.
      name            = "Weekly"
      start_date      = "2026-09-07"
      participant_ids = [vibeoncall_team_membership.ada.user_id, vibeoncall_team_membership.alan.user_id]
      weekly = {
        start_day  = "monday"
        start_time = "09:00"
        end_day    = "monday"
        end_time   = "09:00"
      }
    },
    {
      # Hands off every Saturday at 09:00. The outgoing participant keeps Saturday until 09:00.
      name            = "Weekend"
      start_date      = "2026-09-05"
      participant_ids = [vibeoncall_team_membership.alan.user_id, vibeoncall_team_membership.ada.user_id]
      weekly_windows = {
        windows = [
          { start_day = "saturday", start_time = "00:00", end_day = "sunday", end_time = "23:00" },
        ]
        hand_off_day  = "saturday"
        hand_off_time = "09:00"
      }
    },
  ]
}
```

## Schema

### Required

- `name` (String) Schedule name, unique within the organization.
- `rotations` (Attributes List) Rotations in display order. Each needs exactly one of `daily`, `weekly`, or `weekly_windows`. Rotations are matched to existing ones by name, and rotations sharing a name by their order, so editing or renaming one keeps its ID and overrides. Changing the order rewrites the rotations in place from their positions. (see [below for nested schema](#nestedatt--rotations))
- `time_zone` (String) IANA time zone the rotation times are in, such as `America/New_York`.

### Optional

- `team_ids` (Set of String) Numeric IDs of the teams that own the schedule. Omit for a global schedule.

### Read-Only

- `id` (String) Numeric schedule ID.

<a id="nestedatt--rotations"></a>
### Nested Schema for `rotations`

Required:

- `name` (String) Rotation name.
- `participant_ids` (List of String) Numeric user IDs in the order they take turns. Removing someone can change who is on call now. For a member of the schedule's team, use `vibeoncall_team_membership.<name>.user_id` and set `create_before_destroy` on that membership, so Terraform removes the user from this rotation before it removes them from the team.
- `start_date` (String) First date the rotation takes effect, in `YYYY-MM-DD` format. The first participant is on call from this date, so it and the participant order together decide who is on call now.

Optional:

- `daily` (Attributes) Hand off every day. Coverage runs from `start_time` to `end_time`; equal times cover the whole day. (see [below for nested schema](#nestedatt--rotations--daily))
- `weekly` (Attributes) Hand off every week, covering one range from `start_day` `start_time` to `end_day` `end_time`. The same start and end covers the whole week. (see [below for nested schema](#nestedatt--rotations--weekly))
- `weekly_windows` (Attributes) Hand off every week, covering several windows. (see [below for nested schema](#nestedatt--rotations--weekly_windows))

Read-Only:

- `id` (String) Numeric rotation ID, used by `rotation_targets` in `vibeoncall_escalation_policy`.

### Nested Schema for `rotations.weekly`

Required:

- `start_time` (String) Time on `start_day` the range starts. A 24-hour time in `HH:MM` format, such as `17:30`.

Optional:

- `daily_end_time` (String) End of the daily hours. A 24-hour time in `HH:MM` format, such as `17:30`.
- `daily_start_time` (String) Limits coverage within the range to these daily hours. A 24-hour time in `HH:MM` format, such as `17:30`.
- `hand_off_day` (String) Hand off on this day, at `hand_off_time` or 00:00, instead of at the range start. A lowercase weekday name, such as `monday`.
- `hand_off_time` (String) Time on `hand_off_day` the handoff happens. Requires `hand_off_day`. Omit it to hand off at 00:00. Coverage on `hand_off_day` before this time stays with the outgoing participant. A 24-hour time in `HH:MM` format, such as `09:00`.
