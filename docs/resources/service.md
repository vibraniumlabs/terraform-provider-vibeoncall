# vibeoncall_service (Resource)

A service in the service catalog, with the teams and users who respond to it and the stakeholders kept informed.

~> **Note** Responders and stakeholders are added after the service is created. If adding them fails, the service is kept and marked tainted, and the next apply replaces it.

## Example Usage

```terraform
data "vibeoncall_member" "ada" {
  email = "ada@example.com"
}

resource "vibeoncall_team_membership" "ada" {
  team_id = vibeoncall_team.payments.id
  user_id = data.vibeoncall_member.ada.id
}

data "vibeoncall_member" "grace" {
  email = "grace@example.com"
}

resource "vibeoncall_service" "checkout" {
  name        = "Checkout"
  description = "Takes payments for every storefront."
  team_id     = vibeoncall_team.payments.id

  responder_team_ids = [vibeoncall_team.platform.id]

  # Ada is on the owning team, so reference her membership.
  responder_user_ids = [vibeoncall_team_membership.ada.user_id]

  stakeholder_user_ids = [data.vibeoncall_member.grace.id]
}
```

## Schema

### Required

- `name` (String) Service name, unique within the organization regardless of case.

### Optional

- `description` (String) Service description. Remove the argument to clear it.
- `external_provider` (String) Provider the service is imported from, such as `backstage`. Set together with `external_service_id`.
- `external_service_id` (String) The service's identifier in `external_provider`, unique per provider within the organization. Set together with `external_provider`.
- `responder_team_ids` (Set of String) Numeric IDs of teams added as responders. The owning team responds without being listed; list it as well to keep it responding after `team_id` changes.
- `responder_user_ids` (Set of String) Numeric IDs of users added as responders. For a member of the owning team, use `vibeoncall_team_membership.<name>.user_id`, so Terraform removes the user from this service before it removes them from the team. For anyone else, use `data.vibeoncall_member.<name>.id`.
- `stakeholder_user_ids` (Set of String) Numeric IDs of users added as stakeholders of the service. Stakeholders matched by a condition set in the app are not managed here.
- `team_id` (String) Numeric ID of the owning team, which always responds to the service.

### Read-Only

- `id` (String) Numeric service ID.
