# vibeoncall_escalation_policy (Resource)

An escalation policy: who is paged, in what order, and how long each tier waits for an acknowledgement. Set a team's default policy with `vibeoncall_team_default_escalation_policy`.

~> **Note** Destroying a policy that is its team's default, including replacing it by changing `team_id`, leaves the team with no default, and the plan does not show it.

## Example Usage

```terraform
data "vibeoncall_member" "ada" {
  email = "ada@example.com"
}

resource "vibeoncall_team_membership" "ada" {
  team_id = vibeoncall_team.sre.id
  user_id = data.vibeoncall_member.ada.id

  lifecycle {
    create_before_destroy = true
  }
}

data "vibeoncall_member" "grace" {
  email = "grace@example.com"
}

resource "vibeoncall_escalation_policy" "sre" {
  name        = "SRE primary"
  description = "Page the primary on-call, then Ada, then the platform lead."
  team_id     = vibeoncall_team.sre.id

  tiers = [
    {
      acknowledgement_timeout_seconds = 300
      schedule_targets                = [{ schedule_id = "12" }]
    },
    {
      # Ada is on the SRE team, so reference her membership.
      acknowledgement_timeout_seconds = 600
      user_ids                        = [vibeoncall_team_membership.ada.user_id]
    },
    {
      # Grace is not on the SRE team, so reference the data source.
      acknowledgement_timeout_seconds = 900
      user_ids                        = [data.vibeoncall_member.grace.id]
    },
  ]
}
```

## Schema

### Required

- `name` (String) Policy name, unique within its team.
- `tiers` (Attributes List) Tiers in escalation order, starting with the first. Each tier needs at least one target. (see [below for nested schema](#nestedatt--tiers))

### Optional

- `description` (String) Policy description. Remove the argument to clear it.
- `team_id` (String) Numeric ID of the owning team. Omit for a global policy. Changing it replaces the policy.

### Read-Only

- `id` (String) Numeric escalation policy ID.

<a id="nestedatt--tiers"></a>
### Nested Schema for `tiers`

Required:

- `acknowledgement_timeout_seconds` (Number) Seconds to wait for an acknowledgement before escalating to the next tier.

Optional:

- `rotation_targets` (Attributes List) Schedule rotations whose on-call is paged. (see [below for nested schema](#nestedatt--tiers--rotation_targets))
- `schedule_targets` (Attributes List) Schedules whose on-call is paged. (see [below for nested schema](#nestedatt--tiers--schedule_targets))
- `user_ids` (List of String) Numeric IDs of users to page. For a member of the policy's team, use `vibeoncall_team_membership.<name>.user_id` and set `create_before_destroy` on that membership, so Terraform removes the user from this policy before it removes them from the team. For anyone else, use `data.vibeoncall_member.<name>.id`.

<a id="nestedatt--tiers--rotation_targets"></a>
### Nested Schema for `tiers.rotation_targets`

Required:

- `rotation_id` (String) Numeric ID of a rotation in that schedule.
- `schedule_id` (String) Numeric schedule ID.

Optional:

- `mode` (String) Who to page: the `current`, `next`, or `previous` on-call. Defaults to `current`.


<a id="nestedatt--tiers--schedule_targets"></a>
### Nested Schema for `tiers.schedule_targets`

Required:

- `schedule_id` (String) Numeric schedule ID.

Optional:

- `mode` (String) Who to page: the `current`, `next`, or `previous` on-call. Defaults to `current`.
