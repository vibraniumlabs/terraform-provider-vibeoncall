# vibeoncall_maintenance_window (Resource)

A maintenance window: a planned period during which matching alerts do not page anyone. Alerts are still ingested and created. Suited to planned, short-lived windows.

~> **Note** Once `start_at` has passed, the window's `start_at` cannot change, and changing `team_id` fails at plan time because it would replace the window. Once `end_at` has passed, the window cannot change at all. To keep an ended window in the app's history when you remove it from your configuration, use a `removed` block with `destroy = false`; destroying it deletes it from the app.

## Conditions

`condition_groups` takes the same shape the app's condition editor builds. An alert is covered when it matches any group. Inside a group, `operator = "AND"` requires every condition and `operator = "OR"` requires any. Each condition sets exactly one of `severity`, `field`, `provider` or `time`.

To express `A AND (B OR C)`, write it as two groups: `(A AND B)` and `(A AND C)`.

Coming from an Opsgenie maintenance that disables one integration, use a single group with a `provider` condition naming that alert source.

## Example Usage

```terraform
resource "vibeoncall_maintenance_window" "db_upgrade" {
  name        = "Postgres upgrade"
  description = "Primary database failover and upgrade."
  team_id     = vibeoncall_team.sre.id
  start_at    = "2026-11-20T09:00:00+08:00"
  end_at      = "2026-11-20T11:00:00+08:00"

  announcement_channels = [data.vibeoncall_chat_channel.incidents.id]

  # Covers Datadog or Grafana alerts at SEV3 or below.
  condition_groups = [{
    operator = "AND"
    conditions = [
      { provider = { providers = ["datadog", "grafana"] } },
      { severity = { operator = "greater_than_or_equal", severity = "SEV3" } },
    ]
  }]
}

resource "vibeoncall_maintenance_window" "staging_nights" {
  name     = "Staging, nights and weekends"
  start_at = "2026-11-20T00:00:00Z"
  end_at   = "2026-12-20T00:00:00Z"

  # Groups are joined by OR: staging alerts at any time, or any alert at night or on weekends.
  condition_groups = [
    {
      operator = "AND"
      conditions = [
        { field = { field_path = "details.env", operator = "exact_match", value = "staging" } },
      ]
    },
    {
      operator = "OR"
      conditions = [
        { time = { timezone = "Asia/Taipei", daily = { start_time = "22:00", end_time = "07:00" } } },
        { time = { timezone = "Asia/Taipei", weekly = [{ start_day = "saturday", end_day = "sunday", start_time = "00:00", end_time = "23:59" }] } },
      ]
    },
  ]
}
```

## Schema

### Required

- `end_at` (String) RFC 3339 end time, after `start_at`. To end an active window early, set it to a time a few minutes ahead. A window that has ended cannot be changed.
- `name` (String) Window name.
- `start_at` (String) RFC 3339 start time, such as `2026-11-20T09:00:00+08:00`. A new window cannot start in the past, and a window that has started cannot change it.

### Optional

- `announcement_channels` (Set of String) IDs of the Slack or Microsoft Teams channels to announce the window's start and end in, from `data.vibeoncall_chat_channel.<name>.id`.
- `condition_groups` (Attributes List) Limits which alerts the window covers. An alert is covered when it matches any group. Omit to cover every alert of the team, or of the organization for a global window. (see [below for nested schema](#nestedatt--condition_groups))
- `description` (String) Window description. Remove the argument to clear it.
- `team_id` (String) Numeric ID of the team whose alerts the window covers. Omit for a global window that covers every team. Changing it replaces the window, which fails once `start_at` has passed.

### Read-Only

- `id` (String) Numeric maintenance window ID.

## Import

Import is supported using the following syntax:

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
# Import by numeric maintenance window ID.
terraform import vibeoncall_maintenance_window.db_upgrade 42
```

An imported window reads `start_at` and `end_at` back in UTC. If your configuration writes them with another offset, the first plan after import shows an update that changes only their format and sends nothing to the API. A window whose conditions the app's editor cannot build, such as a group nested in a group, cannot be imported. If such conditions are written through the API to a window Terraform already manages, the next plan shows them as changed and the apply replaces them with your configuration.
